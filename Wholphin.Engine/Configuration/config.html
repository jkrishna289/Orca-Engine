Features

Content-based "Because You Watched X" / "More Like This" rows.
Mixes a small share of novel, unfamiliar-genre picks into recommendations to avoid a filter bubble.
Lets the app request unavailable titles through the engine via Jellyseerr.
Pulls TMDB titles matched to each user's taste (You Might Like / Because You Watched) plus the trending and per-country rows. Every imported title carries a per-user justification; nothing is imported blindly. Needs a TMDB key.
Strict release events since the user's last visit: a movie that became available, or a series whose episode aired or downloaded. No backlog.
Series the user started but hasn't finished: skipped earlier seasons and abandoned shows (the correct home for backlog).
Upcoming episodes/releases for catalog titles, from the *arr calendar (or TMDB).
Themed rows (Mind Bending, Dark Thrillers, Feel Good, …) rotated daily.
Server pre-fetches + transcodes low-bitrate trailers for card-focus previews. Requires yt-dlp and ffmpeg installed on the server; dormant otherwise.
Groq generates a per movie/series content-warning card shown briefly at the start of playback. Needs a Groq API key (below); pre-generated in the background and cached.

AI (any OpenAI-compatible LLM)

Optional. A hosted (or local) LLM powers the "For You" re-ranker, AI discovery picks, trivia and content advisories. The engine works fully without it; recommendations are always computed locally first. Only anonymized taste summaries + public title metadata are sent, never account identity. Defaults to Groq; set a base URL to use OpenAI, Ollama, OpenRouter, LiteLLM, etc.

The LLM proposes new titles from each viewer's watch history and becomes the primary source for "You Might Like" / "Because You Watched" (TMDB fills when it under-delivers). Rows only: never requests anything. Needs a TMDB key too.
The LLM curates every personalized surface: For You + Spotlight (genuine selection from a wide local pool), mood collections, More Like This, and Coming Soon ordering. List rows (trending, country, recently added) stay algorithmic. Each surface falls back to the local engine on any failure.

Embeddings (similarity vectors)

How "More Like This" / "Because You Watched" content vectors are produced. Default is local TF-IDF (free, on-device). Cloud/local-neural options give stronger semantic similarity; the engine falls back to TF-IDF when the chosen provider is unconfigured or fails. (Groq has no embeddings API, so it isn't an option here — it powers the re-ranker above.) Only the keys for the selected provider are needed.

Path to an ONNX sentence-transformer model on the server. On-box inference isn't implemented yet, so selecting ONNX currently falls back to TF-IDF.
